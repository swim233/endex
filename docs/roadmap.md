## 已完成

### M1 能搜（`d2cd915`）

- **仓库：** cargo workspace（`endex-core` 库 + `endex-cli`），`justfile` 统一入口。
- **推理：** EmbeddingGemma 2（768 维，文字和图片同一空间），走 LiteRT-LM C API，自写 FFI，`dlopen` + `RTLD_LOCAL`。建库用 GPU（Vulkan），失败退回 CPU；查询固定用 CPU。LiteRT 和 ONNX Runtime 在同一进程里共存没有问题，不需要拆 worker 进程。
- **OCR：** oar-ocr + PP-OCRv6（CPU），带乱码过滤。
- **解析与切块：** Markdown 按标题、纯文本/代码按行窗口、docx 按段落；每块不超过 480 个模型 token。
- **存储：** LanceDB 存块和向量，SQLite 存文件清单；增量更新看 mtime + BLAKE3 哈希。
- **关键词：** jieba 分词（去掉中文虚词）+ 标识符拆分 + 文件名前缀 n-gram，交给 LanceDB 做 BM25。
- **检索：** 向量 / 关键词 / 混合（RRF k=60，同分时向量结果优先），文档和图片分组，每个文件只出一条。
- **命令：** `endex index --manifest`、`search`、`eval`、`status`、`config`；`--data-dir` 隔离索引。
- **评测：** 改用 4 个公开数据集（私有截图评测推迟），`just eval` 一条命令完成准备、建库、评测。100 条查询的最好成绩：

  | 数据集 | 最好模式 | R@10 / MRR |
  |---|---|---|
  | XM3600 中文（描述 → 照片） | 向量 | 1.000 / 0.924 |
  | MIRACL-VISION 中文（问题 → 网页截图） | 混合 | 0.964 / 0.850 |
  | T2Retrieval 中文（问题 → 段落） | 混合 | 0.818 / 0.888 |
  | SciFact 英文（论断 → 摘要） | 混合 | 0.940 / 0.803 |

  完整结果和建库耗时见 [m1-eval.md](m1-eval.md)。
- **质量：** QA 三轮，第一轮 19 个问题全部修复，第三轮通过。

### M2 能唤出（`0a4cf02` 原型，`28ecfb7` 正式版）

- **第 0 阶段原型：** 你在真实桌面上验证了 LayerShellQt 浮窗、快捷键唤出时的焦点、fcitx5 中文输入和剪贴板。结论：用 top 层（overlay 层会把输入法候选框压在下面），唤出时独占键盘。
- **endexd 守护进程：** zbus 服务 `org.endex.Daemon1`（`/org/endex/Daemon`），提供 `Search`、`Preview`、`Status` 三个方法，接口版本 1。
  - 只读；常驻 CPU 查询模型。每次查询前切到最新表版本，所以命令行重建索引后不用重启。
  - 同一客户端的新查询会取消旧查询；查询截到 512 字。
  - 第二个实例直接退出，不抢总线名；启动出错时退出码为 2，systemd 不会反复重启。
- **endex-ui 浮窗：** QML + C++，1100×640，跟随 Plasma 配色，中文界面。
  - 边输入边搜（120 ms 防抖，过期结果丢弃）。混合 / 向量 / 关键词三种模式，`Ctrl+1/2/3` 切换。
  - 文档每页 8 条，图片三列网格每页 9 张，两组各自分页；每条结果显示相关度数字，混合模式下额外标出「关键词 #n」。
  - 右侧固定预览：文档显示片段和高亮，并能翻到前后片段；图片显示大图、OCR 文字和尺寸。
  - 五个操作：打开、在 Dolphin 中显示、复制路径、复制片段、找相似（找相似是灰的，留到 M4）。有右键菜单；`Esc` 先关菜单，再关浮窗。
  - 点浮窗外面会关闭（点任务栏除外，你已接受）。
  - 状态界面：空查询、无结果、首次运行（显示命令行提示）、守护进程未运行（带「启动」按钮）、正在重建、搜索失败。
  - 安全：所有索引里的文字都按纯文本显示，浮窗只允许加载本地文件，不发网络请求。
- **命令行与安装：** 新增 `endex toggle` 和 `endex search --daemon`。`just install` 和 `just uninstall` 只碰用户目录：`~/.local/bin`、D-Bus 服务文件、systemd 用户单元。
- **实测：** 在 SciFact（6,092 块）上，经 D-Bus 的混合查询约 50–60 ms，关键词约 8–10 ms（目标 ≤150 ms）。endexd 常驻内存约 0.92 GB，启动 0.35–0.55 s。命令行和守护进程的结果在 30 条查询上一致；M1 评测数字不变。
- **质量：** QA 三轮。
  - 第一轮：严重问题是文件标题能让浮窗加载网络图片。
  - 第二轮：较严重问题是清单里跳过的行会导致索引被删。
  - 第三轮：通过。
  - 之后你在真实桌面上做了验收和复测，全部通过。
- **测试：** `just check`、`just ui`、`just dbus-test` 都通过。

### M3 保持新鲜（`7d97e7e`）

- **Part A：守护进程负责建索引**（QA 三轮后通过）
  - endexd 是唯一写入者：`<data_dir>/endex.lock` 上的 flock，第二个写入者起不来；`endex index` 只能写 `--data-dir` 指定的隔离索引。
  - 按 `config.toml` 里的目录（`[index] sources`，每个目录可选 文档和图片 / 仅文档 / 仅图片）扫描和监听。增量扫描（启动时 / 每小时 / 每天）和 inotify 实时监听可以分别开关；inotify 上限时退回每小时扫描。
  - 排除规则：`.gitignore`/`.ignore`（含 git 仓库里的上级目录，不读主目录本身的）、内置构建产物清单、敏感文件清单（命中的文件不打开）、隐藏文件、额外规则、单个文档大小上限。
  - 暂时不可用的目录（拔掉的移动盘、被卸载）保留已索引的文件，回来后重新扫描，不会把索引清空。
  - 资源：电池供电暂停（「本次继续」可临时继续）、低优先级（nice 19 + idle IO）、轻 / 中 / 重线程档位、首次建库和大批量走 GPU、零星改动走 CPU、GPU 闲置 2 分钟释放。
  - 改模型、前缀或 OCR 设置后停止索引，等「重建索引」；重建时清空再重填，期间照常可搜（结果不完整）。崩溃或 `kill -9` 后下次启动接着做完。
  - 设置：`GetSettings` / `ApplySettings`（逐项检查，写回 `config.toml` 时保留注释），手改文件也会自动重载；文件坏了就沿用上一次能用的设置并报告错误。
  - D-Bus 接口升到版本 2：`Status` 加了很多键，新增 `IndexState` 属性和 `Pause`、`Resume`、`ContinueOnBattery`、`Rescan`、`Rebuild`、`Retry`、`FailedFiles`、`CheckPath`、`ReportUsage`、`RecentQueries`、`UsageLog`、`ClearUsageLog`。
  - 实测：改一个文件后约 0.6 s 能搜到；OCR 批量建库时混合查询 p95 115 ms（目标 ≤150 ms）；空闲释放后常驻内存回到 M2 的约 0.96 GB；10 万个文件用 1,021 个 inotify watch，重启后 2.2 s 回到空闲。
- **Part B：设置窗口、首次运行、浮窗状态**（QA 三轮后通过）
  - **设置窗口：** Kirigami，跟随 Plasma 配色，一个会话只有一个窗口。左侧八个分类（索引目录、排除规则、增量与监听、模型与设备、索引状态、快捷键指引、资源档位、评测与日志），文字和顺序同原型。改动先留在窗口里，「应用」才写入 `config.toml`，「还原」放弃；底部显示有几处没应用，侧栏标出有改动或有错的分类；有没应用的改动时关窗口会先问。
  - **打开方式：** 浮窗的齿轮或 `Ctrl+,`、`endex settings [页面]`、应用菜单里的「Endex 设置」（`just install` 装到 `~/.local/share/applications`）。窗口已经开着时会被带到最前面并切到指定页。
  - **首次运行：** 没有配置目录时，浮窗显示简短引导，按钮打开设置的「索引目录」并显示欢迎提示。`~/Documents`、`~/Pictures` 列在「需要你决定」里，默认不索引。浮窗里所有指向 `endex index` 的命令行提示都去掉了。
  - **浮窗：** 状态栏显示索引状态（索引就绪 · 文件和片段数、索引中 x / y · GPU 批量、索引已暂停 · 电池供电、尚未配置索引目录等）；顶部横幅显示建库或重建进度（「搜索结果可能不完整」）、电池暂停（本次继续 / 资源档位）、出错（原因和「继续」，不自动重试）、需要重建；配置文件有错误时状态栏显示文件路径。空查询时列出最近搜索（↑↓ 选择，Enter 重新搜索）。每次唤出最多记一条使用日志（打开了结果，或者搜过之后关掉浮窗），不按键记录。
  - **评测：** `endex eval --sets` 跑 `<data_dir>/eval/` 下的全部公开评测集，严格只读（用 strace 和文件哈希确认评测目录里什么都没写），结果存到 `<data_dir>/eval-results/last.json`；设置窗口里「运行评测」在后台调用它。数字和 M1 完全一致。
  - **测试环境：** 嵌套 KWin 测试环境加了写入者模式（临时 `--config`，数据目录和索引目录都在草稿目录里，启动前检查），所有进程都用临时的 XDG 目录；文件夹对话框会显示真实主目录，所以自动测试里不点它。
- **质量：**
  - Part A 的 QA 三轮。第一轮的严重问题有两个：索引目录临时不见时整个目录的索引被清空；建库途中改设置，已排队的文件不受影响。第二轮的较严重问题是写坏的 `--config` 会借用别的配置留下的副本。第三轮通过。
  - Part B 的 QA 两轮。第一轮的较严重问题是守护进程后启动时设置窗口不刷新；第二轮通过。
  - 你在真实桌面上验收，全部通过（电池那一步跳过）。浮窗一开始没出现，是 KDE 快捷键命令末尾多了一个换行，你手动改好了。验收后按你的要求加了「立即重启」按钮，QA 检查通过。

### 当前安装状态

- 装的是 M3 版本，`endexd` 用户服务处于启用状态并在运行，是自己索引的唯一写入者。
- 索引哪些目录由你在设置窗口的「索引目录」里决定。
- 快捷键是你在 KDE 里手动绑定的，指向 `~/.local/bin/endex toggle`。

### 已知限制（已接受或留到后面）

- 点任务栏或面板不会关闭浮窗（面板不抢焦点）。
- 图片格子下的 OCR 文字超长时直接截断，没有省略号。
- 浮窗固定 1100×640，屏幕很矮时会被裁掉。
- 每次唤出都会把上次的查询重新搜一遍，好让索引的变化及时显示出来。
- 常驻模型占约 0.92 GB 内存。
- 预览显示的是位置（标题路径或段落范围），不是逐行行号。
- 截图和普通照片在界面上不区分：有 OCR 文字就显示一行文字，没有就标「语义匹配」。
- 规划时选的「打开并跳到命中位置」目前只做到用默认程序打开文件，还没有跳到命中位置；归到哪个里程碑待定。
- （M3）Wayland 下，从终端运行 `endex settings` 时，已经开着的设置窗口会先隐藏再重新显示，这样才能拿到焦点；从应用菜单打开时用的是启动器给的激活令牌。
- （M3）设置窗口第一次打开后留在内存里（endex-ui 从约 275 MiB 增加到约 340–360 MiB），关掉窗口也不释放。
- （M3）「运行评测」会另起一个 `endex` 进程，再载入一份查询模型，大约跑一分钟。
- （M1 起就有）LiteRT 的 xnnpack 缓存（`<data_dir>/cache/litert`）由 endexd 和命令行共用；两边同时重建缓存时（例如换模型后马上运行评测）可能互相干扰。平时只读，不受影响。

### 和原计划不一致的地方

- PDF 从 M1 挪到 M5，和其他格式一起做。
- M1 的评测改用公开数据集，私有截图评测推迟到 M3 之后。`endex sample` 命令保留，但没有在你的真实文件上运行过；早先生成的路径清单已按你的要求删除。
- M3 的 D-Bus 接口没有照原计划做 `Reindex` 和进度信号，而是 `Rescan`、`Rebuild`、`Pause`、`Resume`、`ContinueOnBattery` 加上可订阅的 `IndexState` 属性。
- M3 在原型之外加了几样：「增量与监听」页的「立即扫描」按钮；验收后按你的要求，「需要重启」提示里加了「立即重启」按钮（用 `systemctl --user restart endexd`，失败时仍可复制命令）；`org.endex.Ui1.ActivateSettings`，让应用菜单打开的设置窗口能拿到焦点；`IndexState` 里的 `images`，用来提示图片多时改用「重」档。

## 剩余计划

### M3 之后

- 由你决定什么时候把 `~/Documents` 和 `~/Pictures` 纳入索引（设置窗口「索引目录」里的「需要你决定」）。图片多时首次建库主要花在 OCR 上，可以临时把「资源档位」改成「重」。
- 私有截图评测：需要重新抽样。你先剔除敏感图片，我再看图起草查询，由你修改定稿。
- M3 实测里看到、可以放进 M4 的几件事：
  - 10 万个片段时一次查询约 0.3 s（精确向量扫描），超过 150 ms 的目标。近似索引（ANN）可能要早于「超过 10 万个文件」再做。
  - 默认「中」档下 OCR 每张约 1.2 s，边搜边建时约 4 s，图片多的首次建库要几十分钟。
  - 设置窗口打开时每 2 秒查一次 `Status`，索引很大时可以放慢或缓存。
  - 「打开并跳到命中位置」还没归到哪个里程碑。

### M4 更准

- `Ctrl+R` 按需重排：在 GPU 上用 Qwen3-Reranker-0.6B 精排前 30 条文本结果，默认关闭。
- 按目录、类型、时间过滤。
- `Ctrl+S` 找相似（M2 已留了按钮位置）。
- 模糊匹配。
- 融合调优：加权融合，或者给关键词分设下限，避免照片里偶然的一个 OCR 词和最好的向量结果平起平坐。
- 繁简折叠（如 OpenCC），用于 OCR 文字和查询。
- 用评测集决定：查询前缀的写法、要不要截短向量维度、图片要不要另加 FG-CLIP 2。
- 文件数超过 10 万时再建近似索引（ANN）。

## 工作方式

- **流程：** 每个里程碑开工前先征得你同意。由开发代理写代码、QA 代理审查，问题交回开发修复，直到 QA 通过。最后你用可点击的验收清单在真实桌面上验收。提交和合并由你决定，不推送。
- **隐私：** 开发和测试只用合成数据和公开评测集，不读取你的真实文件，也不把个人信息放进任何网络请求。
- **测试：** 只写必要的单元测试和 D-Bus 接口级集成测试，不过量。浮窗的自动检查只在嵌套 KWin 测试环境里跑，固定使用嵌套的 Wayland 连接，每次运行后检查有没有泄漏到真实桌面；代理不碰你正在用的会话总线和 systemd 用户服务。
- **验收：** Part B 通过 QA 后，你用可点击的验收清单在真实桌面上验收：先用 `~/endex-test/` 里的合成目录过一遍，最后由你决定是否加入 `~/Documents`、`~/Pictures`。
